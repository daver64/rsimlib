# Blender and glTF workflow

simlib's model format is **glTF 2.0 (`.glb`)**. Blender 4.x reads and writes it natively, so Blender stays
external tooling: nothing in the library or at runtime calls Blender.

## Blender to simlib

```
blender --background model.blend --python tools/blender/export_glb.py -- out.glb [--no-anim] [--selected]
```

[export_glb.py](../tools/blender/export_glb.py) uses the settings simlib is tested against: Y-up, modifiers
applied, and NLA strips exported as separate named clips (play them with `sl::play_model_clip()`).
Blender key times start at the action's first frame, so a clip authored from frame 1 at 24 fps begins at
1/24 s. Draco compression is not used (simlib does not read it). In Blender use File > Export > glTF 2.0 with
the same options if you prefer the UI.

Armatures export as glTF skins and bone animations (NLA strips become clips); materials export as PBR
(Principled BSDF base colour, metallic, roughness, emission and normal maps; an emission texture is ignored by
simlib). See "Skinned models" and "PBR materials" in the [API reference](api_reference.md#3d-surfaces-includesurface3dh)
for what simlib supports. The fixtures `tests/fixtures/gltf_skin.glb` and `gltf_pbr.glb` are regenerated by
`make_gltf_skin_fixture.py` and `make_gltf_pbr_fixture.py` next to them.

### Build-time export with CMake

```cmake
include(SimlibBlender)   # provided by find_package(simlib), or include cmake/SimlibBlender.cmake from the repo
simlib_add_blend_model(TARGET ship_model SOURCE assets/ship.blend OUTPUT ${CMAKE_BINARY_DIR}/assets/ship.glb)
add_dependencies(my_game ship_model)
```

The `.glb` is regenerated when the `.blend` changes. Blender is optional: if `BLENDER_EXECUTABLE` is not found
the target does nothing and a message is printed. Options: `NO_ANIMATION`, `SELECTED_ONLY`.

## AC3D / FlightGear to glTF

```
build/simlib_convert path/to/aircraft.ac out.glb
build/simlib_convert path/to/FlightGear/Models/c172p.xml out.glb --animations out.json
```

`simlib_convert` loads `.ac`, `.xml` (FlightGear), `.obj` or `.glb` and writes a `.glb` that imports into Blender 4.x
(parts, tints, textures, normal maps, double-sided and alpha-mask materials, node hierarchy and clips). It opens a
small window because meshes go through the graphics backend. FlightGear property animations and visibility rules have
no glTF equivalent: they are not written, but `--animations` saves them in simlib's JSON animation format, which
`exmodel3d --animations` and `load_model_animations_json()` read.

From code: call `sl::set_mesh_cpu_data_retained(true)` before loading (meshes are GPU-only otherwise), then
`sl::save_model_gltf(model, "out.glb")`.

## Tests

`ctest` covers the writer round trip (glTF and AC3D), the converter, and (when Blender is installed) exporting
Blender's default scene with `export_glb.py` and loading it. The test fixture `tests/fixtures/gltf_blender.glb` is
regenerated by `tests/fixtures/make_gltf_fixture.py`.
